## 交付

- `codex-switch.cmd` 改为项目相对脚本路径，保留不带名称列出和带名称选择的 CLI 入口。本票不修改 `switch-account.ps1`。
- `AccountList.ps1` 的 `Get-SwitchAccountNames -Root` 仅枚举 `accounts` 下文件名，识别 `<名称>_auth.json` 与 `<名称>.json`，去重并排除 `backup-*` 和目录。不读取凭据内容或 `.current`，不声称验证了当前账号。
- `Window.ps1` 显示账号名称、计数或空列表提示；读取失败显示普通错误提示。02/03 的按钮在本票中保留且禁用。
- 所有本票含中文的 PowerShell 文件带 UTF-8 BOM，兼容 Windows PowerShell 5.1。

UI smoke 初次使用 UIA `ListItem` 查询时失败；当前运行环境将经典 WinForms ListBox 暴露为 Pane。改为在本次启动器的直属 PowerShell 子进程窗口中按原生 LISTBOX 类查找句柄，用只读 `LB_GETCOUNT`/`LB_GETTEXTLEN`/`LB_GETTEXT` 验证可见控件的条目。窗口标题、状态与可见性使用 UI Automation；关闭仅向已验证归属的窗口发送 `WM_CLOSE`。异常路径不输出窗口元素树或实际条目名称。

### 独立评审返修：实窗归属隔离

评审指出，仅排除启动前已有 HWND 无法排除同时新开的同标题窗口；列表不符时输出实际条目也可能泄露名称。返修只修改 `tests/Test-WindowSmoke.ps1`，不修改 `Window.ps1`。

窗口选择现以本次 `cmd.exe` 的直属 `powershell.exe` 子进程为准：官方 Toolhelp32 快照读取父子 PID，UIA 在查找时同时匹配固定标题和已验证子进程 PID；验证进程创建时间不早于启动器并持有 Process handle，清理前再次检查进程仍存活、窗口 PID 与已持有进程一致。不枚举任何其他同标题窗口的内部控件。所有列表差异错误均为固定文本。

回归在每次真实 `.cmd` 启动前额外打开一个独立进程的同标题虚构窗口，断言无子进程的诱饵不能被当成启动器，并断言产品窗口验证及关闭后诱饵仍保持打开。仅在断言结束后，按本次明确持有的诱饵进程句柄关闭诱饵。2026-11-20 返修复跑上述 smoke 命令退出 0，两次产品窗 PASS、两次同标题隔离 PASS；Windows PowerShell 5.1 Parser/BOM 复核通过。

调查中 `Get-CimInstance Win32_Process` 在当前沙箱被拒绝，最终测试不再依赖 CIM；回退到已查证的 Toolhelp32 官方接口，无需提权。PowerShell 为控制台宿主，`.NET Process.WaitForInputIdle` 不适用，最终测试以实际 UI 控件断言验证窗口就绪。

测试均在调用后清理自己的 GUID 临时目录，删除前验证目标绝对路径位于系统临时目录且符合本票固定前缀。未访问真实账号目录、未读取真实凭据、未操作 Codex 桌面进程。

## 02/03 接点

`Window.ps1` 的 `New-SwitchWindow -Root` 返回 `Form`、`AccountList`、`StatusLabel`、`SwitchButton`、`SaveButton`、`RefreshAccounts`。

在 `# Tickets 02/03 attach Click handlers...` 注释之前接入事件，或从此位置调用独立的 UI 绑定函数。02 读取 `AccountList.SelectedItem`、绑定 `SwitchButton.Click` 并按选择启用按钮；03 绑定 `SaveButton.Click`、启用保存并在成功后执行 `& $refreshAccounts`。需要给弹窗设置 owner 时使用 `$form`。同一次操作中可临时禁用两个按钮，结果写 `$statusLabel.Text`。刷新会保留仍存在的选择。

本票单元测试中“按钮禁用”断言仅对应 01 初始状态；后续票启用时应替换为后续行为断言。
