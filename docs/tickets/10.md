# 票 10 · 账号与额度共享核心

| 项目 | 约定 |
| --- | --- |
| 负责人 | 账号功能实现智能体 |
| 状态 | 已验收，独立规范和规格复核通过 |
| 交付位置 | src/AccountService.cs、账号存储、切换脚本及核心测试 |

负责身份核对、凭据保存、额度快照、删除及切换事务。

## 验收

用虚构账号验证外部登录、同身份更新、邮箱冲突、凭据失败中止、额度失败仍能切换，以及桌面关闭后的保存顺序。

## 实现与接口

- `CodexSwitch.AccountService` 提供 `List / Save / Delete / Switch`，两个入口使用同一份共享核心。服务 API 不接受窗口对象；`Switch` 的 `Func<string,string,bool>` 分别传递 `Close` 和 `Force`。
- 当前登录先对比凭据字节或一致的用户与工作区，`.current` 只在身份已匹配后消除重复歧义。缺乏唯一代表时独立显示当前登录，保留所有原别名。
- 保存会更新已核对的原身份并支持改别名；重名不会覆盖其他存档。离开时保留已有别名；首次自动保存使用邮箱、工作区和必要短 ID。
- 完整切换持有同一 `.switch.lock`，复用原桌面退出、原子替换与恢复。退出完成后、替换目标前，先保存原登录最终凭据，再采集额度。捕获失败保留最近成功快照及失败尝试时间；凭据保存失败则中止。
- 额度快照按用户与工作区身份绑定，凭据身份未知时按精确字节摘要隔离。改名保留快照；同名重建为其他身份不会继承。所有带真实 `reset_at` 的到期窗口均有文字提示，耗尽窗口另有标记，历史余额不随时间推断增加。

## 文档依据

- 按项目要求查询 Context7 `/dotnet/docs`。检索未精确覆盖 Framework 文件替换语义，继续核实 Microsoft 官方 [`File.Replace`](https://learn.microsoft.com/en-us/dotnet/api/system.io.file.replace?view=netframework-4.8.1) 与 [`FileStream.Flush(Boolean)`](https://learn.microsoft.com/en-us/dotnet/api/system.io.filestream.flush?view=netframework-4.8.1)。结论：替换可保留被替换文件备份；`Flush(true)` 请求写入中间文件缓冲。实现据此保留被替换凭据，并检查实际被替换版本以发现外部竞争。

## 独立评审后的修复

- `BeforeDeparture` 保存及网络捕获结束后，在实际替换 `auth.json` 前重新执行 `BeforeWriteGuard`。模拟桌面中途重新启动时返回 `DesktopRunning`，保留活动凭据。
- `AccountService.CurrentReadFailed` 区分活动凭据读取失败与真正未登录。独占或损坏的活动凭据不再阻断其他已保存账号列表，也不会生成一个伪造的当前账号。UI 与 CLI 实现者已收到属性契约并接入。
- 事务路径改用严格存在性探测：仅文件或目录不存在返回 false，权限拒绝、共享冲突等错误继续传播。活动凭据在保存或切换预检时无法读取，事务立即失败。
- 改名创建新副本后，删除旧名失败会按本次新副本的字节摘要尝试补偿；副本内容已由外部改变时不删除它。旧名不可删除的测试验证无重复残留，并能恢复后重试改名。
- 无邮箱自动命名为 `未命名账号 · yyyyMMddHHmmss`（本地年月日时分秒）；同邮箱不同工作区使用 8 字符短标识，保留已有别名。
