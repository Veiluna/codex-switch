# 03：保存当前登录

状态：实现与独立评审通过。评审者在 Windows PowerShell 5.1 重跑虚构账号与实际窗口测试，退出码为 0。目录联接场景使用获准的沙箱外测试。

## 验收条件

- [x] 用户输入显示名称后能保存当前登录，名单立即更新，重新打开窗口仍可找到该账号。
- [x] 虚构凭据验证中文名称、没有当前登录、命名冲突；取消或保存失败时原存档保持完整。

## 交付与接法

`SaveAccount.ps1` 导出：

- `Save-SwitchAccount -Root <隔离或用户 .codex 路径> -Name <名称>`：返回 `{ Success, Message }`，不输出凭据或异常原文。
- `Connect-SaveAccount -Window $window -Root $Root`：绑定 `SaveButton.Click` 并启用按钮。使用 `Form` 作为模态输入框 owner，读取名称，成功后调用对象的 `RefreshAccounts`；状态写入 `StatusLabel`。操作期间禁用保存按钮，取消或失败后恢复。

主代理已在 `Window.ps1` dot-source 本文件，建立窗口对象后调用一次绑定。此票未编辑 `Window.ps1` 或 01 的按钮状态断言。

新档使用原有 `<名称>_auth.json` 规则；已有 `<名称>.json` 或 `<名称>_auth.json` 都阻止保存，不覆盖。支持中文。拒绝空白、前后空白、路径/控制字符、尾部句点、点开头、`backup-` 前缀、`_auth` 后缀和 Windows 设备保留名，避免路径逃逸、备份过滤或名单解析歧义。保存只复制字节，不改写未知字段，也不把 `.current` 当作所有权证据；此操作不读写 `.current`。

写入与 02 共用 `accounts/.switch.lock`，以 `OpenOrCreate/ReadWrite/FileShare.None` 持有排他锁。源文件使用只读流并阻止并发写/删除；完整内容先写同目录 GUID 临时文件，刷盘并关闭，再以不覆盖的两参 `File.Move` 发布。失败清理本次临时文件；原活动登录和具名存档不被改写。缺失/空的活动文件拒绝保存。路径及现存祖先拒绝重解析点，校验 accounts、auth、锁和两种目标路径。

## 红绿与实际窗口证据

先建立 `tests/Test-Save.ps1` 并调用新保存入口，首次执行退出 1：`SaveAccount.ps1` 缺失（`CommandNotFoundException`）。实现后使用同一核心测试通过，再扩展实际对话框交互。

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File tests/Test-Save.ps1
```

2026-11-20，Windows PowerShell 5.1 下退出 0，输出两条 PASS：

- 假目录测试：中文命名、逐字节保留未知字段、两种旧文件名冲突、大小写与保留名/路径拒绝、缺失登录、账号目录为文件、活动文件被独占、共享互斥锁忙、临时文件清理，以及 accounts 目录联接拒绝（外部虚构目录无写入）。
- 实际 WinForms 测试：创建并显示生产主窗口，通过其 `SaveButton.PerformClick()` 打开真实模态输入框，Windows Forms Timer 在对话框内填写中文名称并点击保存；核验状态、即时名单刷新与按钮恢复。第二次点击实际取消按钮，核验未增加文件、按钮恢复；重建生产窗口仍显示已保存名称。此为程序操作真实控件，不是手工验收，也未通过 Explorer 人工双击。

测试始终使用 `tests/.tmp-save-<GUID>` 下虚构字节；清理前验证绝对路径在本票测试前缀内。没有读取真实账号目录、输出真实凭据或操作 Codex 桌面进程。目录联接指向同一虚构测试树，先解除联接，再清理测试树。

沙箱内 `$env:TEMP` 的最小 `WriteAllText` 后同目录 `File.Move` 也报 Access denied；因此测试目录改到工作区。目录联接创建被沙箱拒绝，随后以已获自动审批的 `require_escalated` 运行同一纯虚构测试，成功通过；没有变更生产代码去绕过此环境约束。

## 边界与后续

不解析凭据的认证含义，非空字节快照不等于核实在线登录有效。目录联接测试覆盖静态重解析点；未模拟恶意进程在校验后替换目录的竞态、磁盘断电或空间耗尽。共享锁覆盖本工具协作写入；不声称阻止其他程序绕过锁修改账号目录。

正式接入后已移除测试中的后备手动绑定，再次运行本票测试，保存、取消、即时刷新和重开均通过，证明生产 `New-SwitchWindow` 默认完成保存事件绑定。
