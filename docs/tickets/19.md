# 票 19 · 账号详情左对齐与全文查看

用户在桌面端看到详情区的滚动条，以及标题、正文和状态提示的起始位置不齐。沿用已选定的 E 双栏方案，本次修改集中在浏览一个账号时的详情面板。[GitHub #15](https://github.com/Veiluna/codex-switch/issues/15)

## 独立设计

账号名、身份字段、额度标题、额度正文、操作组外沿和状态提示共用右栏的内容起点。姓名和常见长度的邮箱、账号 ID、剩余额度与重置时间应能直接读到。主面板取消分段的滚动条；超长内容保留可聚焦的全文入口和复制能力。

独立设计使用 UI UX Pro Max 核对截断后的全文入口，使用 Design Taste 检查间距和左边线，参考 Cult UI 的 `minimal-card` 标题和正文关系，依花叔设计的实窗复核方法对照历史截图。shadcn MCP 用于查阅参考组件。Context7 的 `/websites/learn_microsoft_en-us_dotnet_desktop_winforms` 用于核对 TableLayoutPanel 中子控件的对齐、Margin 与父容器 Padding。界面由 WinForms 原生控件实现。

## 本地验收

- 用实际额度格式生成虚构快照，核对两个窗口的剩余比例、重置提醒和独立的 Credits 余额。超长文本按完整行显示省略号，全文窗口从原始详情读取数据，包含状态及失败记录。
- 主详情三个预览的实际窗口样式均无滚动条。键盘可以打开全文、选择和复制文本、按 Esc 返回。截图模式下桌面 UI 的 91 项检查通过。[实窗截图](../design/v042-details.png)
- 本机在 175% 显示缩放下检查了普通内容、最小窗口和长详情。系统工作区会限制窗口高度。150% 实机及紧凑布局断点两侧的独立显示环境尚未验证。
- v0.4.2 桌面 EXE 通过五种虚构登录状态的真实入口测试。同次构建的安装器通过隔离目录安装、重复安装与卸载，npm 包通过离线入口验证。交付文件及嵌入资源与构建摘要一致，本机 Defender 扫描均通过。
