## 实现与接口

- `AccountSwitch.ps1` 导出 `Invoke-SwitchAccount -Root -Name -BeforeWriteGuard`；返回 `Success/Changed/Code/Message/BackupPath`，不输出凭据。`Changed` 表示活动登录是否改变；仅修正 `.current` 时为 false。
- GUI 与 CLI 共用核心。CLI 支持 `-Root`，默认 `CODEX_HOME`，否则 `%USERPROFILE%\.codex`；不调用 `codex login status`，避免输出账号详情。
- `New-SwitchWindow -SwitchAction` 和返回对象的 `SetSwitchAction` 是票04回调入口；回调按命名参数 `-Root/-Name` 调用。按钮、Enter 与真实列表行左键单击共用 `InvokeSelectedAccount`；选中、刷新、空白行单击不切换。
- `BeforeWriteGuard` 在持锁且写入前执行，必须只返回一个 Boolean true；false/空/异常拒绝操作。票04负责唯一真实桌面识别守卫，CLI 不提供绕过开关。
- 与票03共用 `accounts/.switch.lock`、`FileStream(OpenOrCreate, ReadWrite, FileShare.None)`。持锁期间读取快照与写入；同目录独占临时文件写入并 flush，已有文件使用 `File.Replace`，新文件 `File.Move`。PS5.1 给 Replace 的第三参必须用 `NullString.Value`，避免 `$null` 变为空路径。
- 目标须为有效 UTF-8 JSON 对象，空文件、损坏 JSON、数组拒绝；未知合法字段始终按原字节保存。检查安全文件名、绝对 Root 以及路径各级 reparse point；读取既有安全名称不套用新建名称的100字或 `_auth` 末尾限制。
- 替换既有活动文件时原子捕获唯一 `backup-<GUID>_auth.json`，但实际字节已相同则不产生凭据备份，仅按需修正 `.current`。更新 marker 失败且未遇到外来更新时恢复活动文件；原先无活动文件则恢复其缺失状态。竞争或回滚失败返回对应失败码并保留恢复版本。
- `.current` 只作为查找线索。仅实际登录与原具名档的用户+工作区均匹配，或同次登录的 `login_owner_id+account_id` 均匹配时回写刷新凭据。工作区相同而用户不同、标识缺失、解析失败都保持未知归属，不覆盖具名档。选择当前同一身份时保留当前较新的凭据。

## 文档核实

- Context7 `/dotnet/docs` 确认 FileStream 通过 FileMode/FileAccess/FileShare 控制创建、访问及共享；原子替换细节另核实 [Microsoft File.Replace](https://learn.microsoft.com/en-us/dotnet/api/system.io.file.replace?view=netframework-4.8.1)：源/目标须同卷，备份参数可为null。临时文件放目标同目录。
- Context7 `/openai/codex` 与 [官方 token_data.rs](https://github.com/openai/codex/blob/main/codex-rs/login/src/token_data.rs) 明确：`login_owner_id` 标识同次登录且token轮换保持；JWT auth claims的 `chatgpt_user_id`（fallback `user_id`）是用户标识，`chatgpt_account_id` 是组织/工作区。只做本机归属比较，不联网、不把解析JWT当作远端认证。

## 边界

- 工具前提为本机凭据文件存储模式；不读取系统凭据仓库，不验证凭据能否远端登录。
- 缺少可核实身份的旧格式仍会保留最新独立备份，但不会自动覆盖可能属于别人的命名档；用户可通过“保存当前登录”建立新的具名档。该档再次被选中时能否登录仍取决于其有效性。
- auth 与 marker 是两个独立文件，无法承诺跨文件断电事务；异常可回滚，断电后保留独立备份且 marker 不作为归属证明。没有声称完成真实账号切换或崩溃断电实测。

## review02 返修与复验

- 评审复现：活动 `auth.json` 为0字节时，`$oldBytes = if (...) { ReadAllBytes(...) }` 的流水线枚举把空数组变成null；以及guard前采快照可能丢掉退出期间落盘的新凭据。
- 先加回归红测，Windows PowerShell 5.1 在“An empty active file is backed up and switching succeeds”断言失败。修正为guard成功之后直接赋值到 `[byte[]]$oldBytes`，不通过if语句的输出采集字节。
- auth提交在最后阶段验证活动文件存在性与字节快照；按 `ExpectedExists` 固定使用Replace或不覆盖Move，不再二次Exists改变原语。活动文件消失/突然出现均报告 `ConcurrentChange`。
- 既有auth的备份改由 `File.Replace` 的唯一 `backupFileName` 原子捕获实际被替换版本，不再提前复制旧快照冒充提交时版本；捕获版本与快照不同时停止正常提交，按实际捕获的版本恢复。备份路径不预创建、不覆盖已有档。
- 回滚先比较活动文件仍是本次写入的字节；观察到外来更新时直接停止回滚。回滚Replace本身也捕获实际被替换版本；若竞争发生在比较与替换之间，保留该更新并最多尝试3次将它放回，任何未解决竞争均报告失败，保留 `backup-recovery-*` 供恢复。原先无auth的回滚使用不覆盖Move保留被移走版本，避免盲目Delete外来更新。
- 新增可控真实I/O回归：0字节活动文件、guard期间更新、提交前更新、Replace调用边界更新、marker失败前更新、回滚Replace边界更新、首次Move前出现新文件、Replace前文件消失；所有用虚构数据、仍委托生产File.Move/File.Replace执行，不冒充真实账号测试。
- 复验：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/Test-Switch.ps1` 通过，包含全部原回归与上述竞争场景；并发失败的临时文件清理断言通过。
- 文档复核：Context7 `/dotnet/docs` 对共享/访问模式仍只给概要，替换与ACL细节再核实 [Microsoft ReplaceFileW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew)：替换可以同时保留被替换版本，源/目标/备份同卷；保留DACL及原属性，不启用忽略ACL或元数据合并错误的选项。错误后若发现备份已生成且活动状态不再是原快照，返回 `RecoveryRequired`，不冒称原文件无变化。
- 并发边界：不遵守本工具锁的外部程序可在任意时刻再次写入，Windows路径替换不提供字节级CAS；实现通过提交前比较、原子捕获实际被替换版本、提交后复核及有限恢复保留遇到的版本，不声称对持续外部写入能无条件完成切换。
