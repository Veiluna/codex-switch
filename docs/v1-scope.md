# Windows 首版需求

用户已在需求访谈中确认以下行为。

| 用户操作或桌面端状态 | 预期结果 |
| --- | --- |
| 双击打开工具 | 出现 Windows 本地窗口，自动列出旧脚本已经保存的账号。 |
| 选择“保存当前登录” | 用户给当前 Codex 登录起名，以后可以在列表里点击该账号。 |
| Codex 已关闭，点击目标账号 | 工具在本机完成切换。Codex 保持关闭。 |
| Codex 正在运行，点击目标账号 | 工具显示目标账号，请用户确认关闭 Codex 并切换。用户确认后，先请求正常退出。 |
| Codex 未能正常退出 | 再次请用户确认是否强制关闭，并提示正在执行的任务可能中断。只有用户明确同意，工具才强制关闭。 |
| 用户取消切换 | 保留当前登录。 |
| 工具为本次切换关闭了 Codex | 确认桌面端已退出，完成账号切换后重新打开 Codex。 |

GitHub 用于分发工具。账号凭据仅在用户本机处理。

## 与旧脚本衔接

旧脚本从 `%USERPROFILE%\.codex\accounts` 查找 `<名称>_auth.json` 或 `<名称>.json`，切换目标为 `%USERPROFILE%\.codex\auth.json`。旧脚本维护的 `.current` 只记录上一次通过脚本选择的名称。用户通过其他入口重新登录后，此标记可能与实际凭据不一致。

迁移后的命令行启动器仍指向已删除的旧脚本位置。旧脚本按 `ChatGPT` 进程名检查桌面端。开发时需独立核实桌面端的识别、退出和重启方式。
