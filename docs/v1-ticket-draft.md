## 01　打开窗口并列出账号

- [ ] 从工作区外启动也能找到项目内脚本。双击图形入口后出现本地窗口，原命令行的列出账号和按名称选择入口仍可用。
- [ ] 使用临时目录中的虚构账号验证两种旧文件名均可识别、备份不出现在列表里；新用户首次打开能看到空列表提示。
- [ ] 在 Windows 上实际打开窗口，记录启动结果。界面和输出仅展示账号名称等必要信息。

## 02　桌面端已关闭时切换账号

- [ ] 从列表选择 B 后，使用虚构凭据验证活动登录已切到 B，桌面端保持关闭。
- [ ] 上一次选择记录与现有凭据归属无法核实时，保留现有凭据的备份，保护具名账号存档。
- [ ] 验收重复点击、目标文件缺失和中途写入失败。界面准确报告结果，原登录可恢复。

## 03　保存当前登录

- [ ] 用户输入显示名称后能保存当前登录，名单立即更新，重新打开窗口仍可找到该账号。
- [ ] 用虚构凭据覆盖中文名称、没有当前登录、命名冲突。取消或保存失败时原存档保持完整。

## 04　关闭、切换和重启桌面端

- [ ] 确认框显示目标账号；首次取消时保持桌面端运行及原登录。
- [ ] 正常退出超时后，明确提示任务中断风险。仅在二次确认后强制关闭已识别的目标桌面端；取消时保留原登录。
- [ ] 确认已退出后切换成功，重新打开本次由工具关闭的桌面端。区分切换失败与切换成功但重启失败。
- [ ] 分别记录受控进程测试与 Windows 桌面端实测结果，标明未实测的分支。

## 05　验证下载和发布

- [ ] 确认目标仓库，检查待发布文件清单，只包含源码、文档和必要的分发文件。
- [ ] 在干净目录按中文说明启动，通过虚构账号完成保存和切换验收。
- [ ] 核验 GitHub 上可访问的代码或发布版本，记录提交标识和下载入口。

## 每张实现票的完成依据

先通过用户入口编写一个失败测试，再实现对应行为。票内记录测试命令、结果、适用的静态检查、独立评审结论，以及需要人工验证的项目。测试使用临时目录和虚构凭据。
